# Code conventions

Ruby and Rails patterns specific to this repository. This file is
intentionally thin at this stage — entries are added only when patterns
stabilise into real conventions, not preemptively.

Conventions derived from architectural decisions are added here only after
the relevant ADR reaches `Status: Accepted`. While an ADR is in `Draft`,
its rules are not yet binding and do not appear in this file.

## Templates

HAML is the template language for all views. ERB is not used.

## Migrations

Primary keys are UUID v7, generated by PostgreSQL (ADR-0003); foreign keys
are UUIDs too. The generators produce this automatically:

    create_table :things, id: :uuid, default: -> { "uuidv7()" }
    t.references :other, type: :uuid

Use `bin/rails generate model` / `migration` rather than writing
`create_table` by hand, so the defaults are not lost. The custom template
`lib/templates/active_record/migration/create_table_migration.rb.tt` was
copied from Rails 8.1 and warns when Rails is upgraded — merge upstream
changes into it when that happens.

## Linting

`qlty check` is the quality gate (`.qlty/qlty.toml`). It runs all linters
below plus Dockerfile (hadolint), shell (shellcheck), secret (trufflehog) and
dependency-vulnerability (osv-scanner) scanners. By default it checks files
changed on the current branch; `qlty check --all` checks the whole repository.

Before every merge, findings on changed files are resolved: fixed, or
suppressed with a short justification. Exception: osv-scanner findings
appear without any code change (new advisories), so they don't hold back
unrelated work — they are handled in dedicated dependency-update issues.

This is a working discipline, not a hard block: nothing on the GitHub side
prevents a merge. CI (M2, #29) reports results.

Individual linters, for quicker runs while working:

- **Ruby** — RuboCop; `.rubocop.yml` is the authoritative config. Run `rubocop`.
- **HAML** — haml-lint. Run `bundle exec haml-lint app/views/`.
- **JavaScript** — ESLint (`eslint.config.js`) for linting, Prettier
  (`.prettierrc`) for formatting. Run `yarn lint:js` to check and
  `yarn format:js` to format.
